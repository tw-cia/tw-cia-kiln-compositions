## What exists in the project

Two Kiln kinds in API group `platform.demotw.com` (`kiln.toml`, namespaced scope):

| Kind | Purpose | Files |
|---|---|---|
| `StaticWebsite` | Private S3 bucket + CloudFront (OAC), bucket policy, optional custom domain with Route 53 alias record | `kcl-scripts/staticwebsite.k`, `staticwebsite_test.k` |
| `DnsValidatedCertificate` | ACM certificate for one domain, validated by Route 53 CNAME records | `kcl-scripts/dnsvalidatedcertificate.k`, `dnsvalidatedcertificate_test.k` |

Shared files:
- `kcl-scripts/schemas_compositions.k`: spec and status schemas for both kinds, plus **narrow hand-written Distribution schemas** (`StaticWebsiteDistributionSpec` and related).
- `kcl-scripts/schemas_providers.k`: imported provider schemas (~5,000 lines, generated by `kiln import`; do not hand-edit).
- `render-fixtures/<kind>/`: `xr.yaml` plus observed-stage files (`observed-1-*.yaml`, `observed-2-*.yaml`).
- `manifests/crossplane-compositions/<kind>/`: generated `composition.yaml` and `xrd.yaml`.

## Issues faced

- **Setup:** missing `kcl.mod`; kiln installed unpinned from GitHub; render needs Docker and the `crossplane` CLI.
- **Size and duplication:** large generated Compositions; each kind embeds its own copy of shared schemas.
- **Hand-maintained narrow schemas** can drift from the CRDs on a provider bump.
- **Tests vs reality:** `kcl test` and `render` did not catch the missing default ProviderConfig, ordering between validation and alias records, or CloudFront deploy time. Fixtures encode our own assumptions.
- **Gaps:** no check that `aliases` requires `certificateArn`; unset optional fields compile to `null`.
- **Operations:** the composition does not manage page content (`index.html`); a `WatchCircuitOpen` condition appeared on the Distribution but the XR still reached Ready.
- **My own mistakes:** wrote scratch logs to `/tmp` more than once; changed a test assertion to fit output without checking the behaviour; first line-classification script was wrong.

## Ideas discussed

1. Run `kcl test`, `generate-all` and `render-all` in CI on every change.
2. Pin kiln, KCL and provider versions; let Renovate/Dependabot open bump PRs.
3. A schema-vs-CRD check script (compare narrow schema fields and types to `crds/`).
4. Generate the narrow schemas from the CRD, or prune the full schemas at generate time to the fields the compose code uses (run the tests against the pruned output too). An LLM is better used to write or review the generator than to run inside the build.
5. A per-kind `typing = "strict" | "loose"` setting in `kiln.toml`; loose leaves `forProvider` as plain dicts and relies on render.
6. KCL supports `from .schemas_providers import X`, but it would not shrink output, since kiln already trims by reachability.
7. Report the blank-line bloat to the kiln maintainers.
